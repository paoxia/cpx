# 产品说明

## 定位

cpx（Agent System）是面向个人开发者和小型技术团队的自托管 AI 开发工作站。用户可以通过 Web 控制台、钉钉或飞书提交开发目标，由本机 Codex 在独立 Git 工作区中持续处理，并按任务来源和授权发布 Pull Request；HTTP 入口用于本地测试和集成调试。系统还提供 GitHub、Skill 插件和 MCP 服务调用能力。

它的核心价值是把远程交代需求、多轮开发和结果回传连接到用户自己的常驻环境中，优先支持 NAS、开发机和单机服务器。当前任务恢复、访问认证和审计的限制见 [安全说明](SECURITY.md)。

## 目标用户

- 需要从聊天工具触发开发任务的开发者。
- 希望将内部工具封装为 Skill 或 MCP 服务的小型团队。
- 需要在自己的服务器上保管配置、令牌和审计数据的自托管用户。

## 核心场景

### 远程触发任务

用户从钉钉或飞书直接发送自然语言，系统通过平台长连接接收并将结果回传到原会话。没有开发任务时，由只读协调 Codex 查询 GitHub、追问仓库并通过受限平台工具创建任务；任务创建后，后续自然语言由 worktree 中的同一 Codex 会话管理。cpx 保留任务生命周期、权限、工具范围和结果回传边界。HTTP `/command` 端点用于本地测试和集成调试。

### 安全地修改 GitHub 内容

用户读取仓库文件，或要求系统在新功能分支上修改、创建文件并生成 Pull Request。系统不会把自动改动直接写入默认分支。

### 扩展外部能力

用户执行已安装的 Skill，或连接 MCP 服务并调用其方法。MCP 支持 stdio、WebSocket 和 HTTP 传输。

### 委托开发任务

用户可在本地 Web 控制台或钉钉、飞书中指定 GitHub 仓库、分支和任务说明。系统从按 owner/repository 分层的完整仓库缓存创建独立 worktree，并允许在同一 Codex 会话中追加多轮 prompt。Web 控制台采用任务列表与连续会话工作台，不提供 Pull Request 发布入口；聊天开发任务默认创建 Pull Request 并异步回推结果。

## 产品原则

- **安全默认**：保护主分支，危险操作显式确认，关键动作留审计记录。
- **自托管优先**：运行数据保存在用户控制的环境中。
- **Agent 主导**：消息理解、仓库选择和任务内需求默认交给 Codex 持续处理，cpx 专注于生命周期、权限和平台边界。
- **统一入口**：不同聊天平台共用同一套任务语义和业务处理器。
- **显式扩展**：Skill 和 MCP 的依赖、权限与连接通过配置声明。
- **结果可追踪**：命令成功、失败和拒绝都应返回清晰结果并记录。

## 当前范围

当前产品包括 CLI 生命周期管理、HTTP 服务、钉钉 Stream 与飞书 WebSocket 长连接、GitHub 仓库/分支查询与文件/PR 流程、聊天及 Web Codex 任务、Skill 执行、MCP 连接、权限确认、审计日志、SQLite 状态存储，以及本机 Codex CLI 登录、模型目录与多配置管理。仓库已提供 Dockerfile、Compose 和不依赖 NAS 终端的极空间部署说明。

远程 Agent 注册、持久化任务队列与重启恢复、内置管理入口认证、Kubernetes 交付物以及企业身份与多租户能力不属于当前已实现范围。SQLite 中已有部分业务状态不代表开发任务已经持久化。
