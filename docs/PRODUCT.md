# 产品说明

## 定位

cpx（Agent System）是面向开发者和小型技术团队的自托管自动化服务。用户可以通过钉钉、飞书或 HTTP 发送文本命令，在受控边界内调用 GitHub、Skill 插件和 MCP 服务。

它的核心价值是把常见开发自动化能力放到一个持续运行、可远程访问并带权限审计的入口中。

## 目标用户

- 需要从聊天工具触发开发任务的开发者。
- 希望将内部工具封装为 Skill 或 MCP 服务的小型团队。
- 需要在自己的服务器上保管配置、令牌和审计数据的自托管用户。

## 核心场景

### 远程触发任务

用户从钉钉或飞书发送命令，系统通过平台长连接接收消息、执行命令并将结果回传到原会话。用户可以查看 GitHub 仓库与分支，把自然语言需求委托给 Codex，并在任务结束后收到状态和 Pull Request 链接；飞书后续自然语言消息可继续同一工作区。HTTP `/command` 端点用于本地测试和集成调试。

### 安全地修改 GitHub 内容

用户读取仓库文件，或要求系统在新功能分支上修改、创建文件并生成 Pull Request。系统不会把自动改动直接写入默认分支。

### 扩展外部能力

用户执行已安装的 Skill，或连接 MCP 服务并调用其方法。MCP 支持 stdio、WebSocket 和 HTTP 传输。

### 委托开发任务

用户可在本地 Web 控制台或钉钉、飞书中指定 GitHub 仓库、分支和任务说明。系统从按 owner/repository 分层的完整仓库缓存创建独立 worktree，并允许在同一 Codex 会话中追加多轮 prompt；控制台仅在用户显式选择后创建 Pull Request，聊天开发任务则默认创建 Pull Request 并异步回推结果。

## 产品原则

- **安全默认**：保护主分支，危险操作显式确认，关键动作留审计记录。
- **自托管优先**：运行数据保存在用户控制的环境中。
- **统一入口**：不同聊天平台共用同一套命令模型和业务处理器。
- **显式扩展**：Skill 和 MCP 的依赖、权限与连接通过配置声明。
- **结果可追踪**：命令成功、失败和拒绝都应返回清晰结果并记录。

## 当前范围

当前产品包括 CLI 生命周期管理、HTTP 服务、钉钉 Stream 与飞书 WebSocket 长连接、GitHub 仓库/分支查询与文件/PR 流程、聊天及 Web Codex 任务、Skill 执行、MCP 连接、权限确认、审计日志、SQLite 状态存储，以及本机 Codex CLI 登录、模型目录与多配置管理。

远程 Agent 注册、持久化任务队列、Docker/Kubernetes 交付物以及企业身份与多租户能力不属于当前已实现范围。后续方向见 [路线图](plans/roadmap.md)。
