# Agent System 规格

状态：当前基线。本文只描述用户可观察行为；实现细节见 [系统架构](../../ARCHITECTURE.md)。

## 目标

系统应允许用户通过聊天平台或 HTTP 入口触发开发自动化任务，并在执行 GitHub、Skill 与 MCP 操作前应用统一权限控制和审计。

## 输入渠道

| 渠道            | 行为                                                           |
| --------------- | -------------------------------------------------------------- |
| 钉钉            | 通过 Stream 长连接接收命令或任务 prompt，并回传异步任务结果    |
| 飞书            | 通过 WebSocket 长连接接收命令或任务 prompt，并回传异步任务结果 |
| HTTP `/command` | 接收 `text`、`userId`、`userName`、`source`，用于本地调试      |
| Web 控制台 `/`  | 管理有序模型配置，创建和取消本机 Coding Agent 任务并查看日志   |
| CLI             | 提供配置、诊断、前后台启停、状态与 npm 更新检查命令            |

非文本聊天消息不在当前范围内。

## Web 开发控制台

- 控制台提供 Codex 登录与多配置页面。用户可新增、删除、保存和切换多套配置，每套包含名称、模型和推理强度，不保存 API Key 或 Base URL。
- 模型目录必须在 Codex 登录后通过 CLI 读取，与交互式 `/model` 使用同一目录；推理强度只能从所选模型声明支持的值中选择。
- 配置按页面顺序写入数据库相邻的 `console-settings.json`，当前配置用于 Web 任务；聊天任务仅在额度或鉴权失败后依次尝试其余配置。不再支持的旧 provider 配置必须在加载时忽略。
- 测试区使用当前配置发起真实 Codex 调用。测试内容最多 4000 字，回复最多 16 KiB；内容和回复不得持久化，不得返回未经解析的 CLI 事件流。模型探测不需要访问项目文件，应允许在 NAS 持久化数据等非 Git 目录中运行；该例外不得应用到正式开发任务。
- 服务提供 Codex 官方设备码与 API Key 登录 API；设备码和账号凭据不得写入项目配置，服务停止时必须清理等待中的登录进程。
- 控制台提供独立 GitHub 页签。没有 Token 时，页面必须提供预填 Contents、Pull requests、Workflows 写权限和有限有效期的 fine-grained PAT 创建入口，并说明选择仓库、生成、复制回填的步骤；cpx 不得声称能从 GitHub PAT 页面自动取得 Token。
- 用户可直接验证 `config.yaml` 或环境变量中的 GitHub Token，也可输入新 Token；状态接口必须返回 `none`、`file` 或 `environment` 来源。新 Token 仅在验证成功后写入 `config/config.yaml`，验证失败不得修改配置，环境变量 Token 不得复制到配置文件。系统分页读取该 Token 可访问的个人、协作及组织仓库。
- GitHub 仓库列表支持筛选，并可将仓库名称带入新任务表单。任务表单也应直接列出当前 Token 明确授权的未归档项目；选定项目后分页读取现有分支，用户可选择一个分支作为任务基线，或输入合法名称新建任务分支，同时保留手动输入仓库地址和基础分支的能力。fine-grained Token 的仓库范围以 GitHub 授权范围为准。
- 仅接受 `owner/repo`、GitHub HTTPS 或 GitHub SSH 仓库地址。首次使用时必须完整克隆到 `repositories/<owner>/<repo>`，后续任务先 fetch 再从该缓存创建独立 worktree 和自动 `cpx/task-<id>` 分支；新建分支时使用用户提供的名称。创建 Pull Request 时必须以所选基础分支为 base。
- 验证成功的 Token 必须立即用于 GitHub API、HTTPS clone/push 和 `gh pr create`。Token 只能通过受控子进程环境和不含密钥的凭据 helper 传递，不得出现在 Git URL、命令参数、任务对象或日志中；SSH 地址继续使用 SSH 凭据。
- Codex 以非交互方式执行。任务可取消，状态包括排队、准备、执行、发布、完成、失败和取消。工作站任务由独立发布服务推送任务分支；基础分支和 `main`、`master`、`production` 由 pre-push hook 拦截，force push 仍然禁止。
- 控制台必须采用任务列表、单任务会话流和统一底部输入框布局；用户可随时新建任务，或在终态任务中从同一输入框追加 prompt。执行中的任务提供停止操作，并允许把新要求保存为待处理消息，由用户随后执行或撤回。
- 左侧任务列表不得产生横向滚动；过长任务标题最多显示两行，并在悬停时提供完整文本。用户展开“运行详情”后，任务轮询刷新不得自动折叠该区域，日志框应保留当前阅读位置；如果用户已滚动到底部，新日志到达时应继续跟随底部。
- 后续轮次复用原 worktree、任务分支和 Codex `thread_id`；每轮必须保存用户 prompt、状态和 Agent 最终回复，以便在会话流中回放。运行日志应作为次级详情折叠展示，不得取代主要对话。Agent 已自行提交或推送任务分支时，发布流程仍须根据相对基础分支的提交差异创建或更新 Pull Request，不能因工作区干净而误判为无改动。
- Web 控制台显示成果 diff、验证记录、发布状态和 PR 链接；按 local/review/auto 策略保留、审查后发布或自动发布。发布绑定成果版本，失败可独立重试，发布前对账已有 PR。
- 任务、状态、轮次、Agent 回复、日志与归属保存到 SQLite；默认最多保留 800 条日志，可配置。队列项恢复，活动项标记 interrupted 后由用户核对恢复；完整仓库缓存与 worktree 保留在磁盘。
- 控制台 API 需要登录或有效访问令牌，浏览器写操作校验 CSRF，服务端校验任务与项目权限；可信网络、TLS 与执行隔离边界见 [安全说明](../SECURITY.md)。

## 命令能力

### 基础命令

- 查看版本和帮助。
- 列出已安装 Skill 和已记录 MCP 连接。
- 使用中文或英文确认、取消待执行的危险操作。

### GitHub

- 聊天命令可查看当前 Token 对应账号和最近仓库，也可按 `owner/repo` 查看现有分支。
- 在配置 Token 和默认仓库后读取文件。
- 为文件修改创建功能分支、提交和 Pull Request。
- 为新文件创建功能分支、提交和 Pull Request。
- 不直接修改默认分支。

自动修改目前只根据描述追加 Markdown 小节，不提供通用代码生成或补丁能力。

### 聊天 Coding Agent

- 飞书和钉钉以自然语言为默认入口。当前会话没有任务时，应启动或恢复一个不绑定仓库的协调 Codex；协调会话必须运行在独立空目录、允许非 Git 工作目录并强制只读沙箱。它应使用与开发任务相同的有序模型配置，并在额度或鉴权失败时顺序回退。
- 协调 Codex 可通过会话范围的 `cpx_platform` 工具查询当前 Token 可访问的 GitHub 仓库和分支，仓库不明确时应追问；只有调用 `task_create` 后才能创建 worktree 开发任务。工具还可列出、查询、继续或停止当前平台用户拥有的任务。
- 消息平台只为 `/new`、`/tasks`、`/status`、`/stop`、`/help` 和确认/拒绝保留确定性斜杠入口。旧文本命令继续兼容，但普通自然语言不得因未配置 `github.defaultRepo` 而被固定格式提示拒绝。
- 钉钉、飞书和 HTTP 命令入口支持 `开发 <owner/repo>[#基础分支] [-> 新分支] <需求>`。基础分支省略时使用仓库默认分支；新分支省略时自动生成 `cpx/task-*`。
- 创建任务前必须确认当前 GitHub Token 能访问目标仓库、仓库未归档、基础分支存在，并在用户指定新分支时确认它尚不存在。
- 聊天开发任务复用 Web 控制台保存的 Codex 配置顺序，启用额度或鉴权失败时的顺序回退，不允许消息覆盖模型、推理强度或 API Key。
- 聊天任务共用项目/实例的 local/review/auto 策略，新安装默认 review，旧安装明确选择迁移策略。发布以所选基础分支为 base；分析或无改动任务不创建空 PR。
- 用户可通过自然语言或兼容的 `继续 <任务ID> <需求>` 追加一轮。建立任务后，除少量斜杠生命周期与确认入口外的文本，包括能匹配旧 GitHub、Skill 或 MCP 命令的文本，都应作为 prompt 继续当前来源会话最近的任务。当前轮次执行中不得并行执行追加要求，只能存为待处理消息；`/new` 应脱离最近任务并开始新的协调会话。
- 消息平台协调会话和开发任务应向 Codex 提供范围受限的 `cpx_platform` MCP 工具：可读取当前平台范围、查询仓库/分支、管理当前用户任务，并可向原会话发送阶段性文本。工具不得接受可更换的用户或会话目标；服务端必须重新校验任务归属，最终回答仍由 cpx 自动回传。
- 创建命令必须立即返回任务 ID；任务完成、失败或取消后，系统通过创建来源的平台原会话推送 Agent 最终文本回答、任务状态和 PR 链接。
- 用户可通过完整任务 ID 或唯一前缀查询、继续、取消任务，并列出最多 10 个最近任务。消息任务仅允许创建它的同一来源平台、同一用户操作；飞书和钉钉的自然语言续写优先限定原会话，即使同一用户从其他会话显式续写，平台工具与异步终态仍回到创建任务的原会话。显式身份绑定与项目权限允许跨入口访问，链接本身不授予权限；未绑定用户不能读取他人任务。
- 消息任务归属、协调会话 ID 和通知持久化；通知采用独立重试和本轮摘要快照，失败不得重跑 Agent。平台事件按持久标识去重。命令受操作黑名单约束并记录审计，身份和项目授权被撤销后拒绝新调用。

### Skill

- 从 npm、Git 或本地标识安装包的底层能力由 `SkillInstaller` 提供。
- 已安装 Skill 可按名称加载和执行，并受可配置超时限制。
- 只有 manifest 声明相应权限时，执行上下文才注入 GitHub 或 MCP 服务。
- 管理员可通过页面及 `cpx skill install/uninstall/list` 管理可信 Skill；执行在受管理子进程，超时/停止会终止进程组。manifest 注入能力、项目范围和只读策略由父进程校验，这不是系统安全沙箱。

### MCP

- 从配置自动连接服务，也可通过命令连接或断开。
- 支持 stdio、WebSocket 和 HTTP 传输。
- 完成 MCP 初始化握手后，以 JSON-RPC 2.0 调用方法。
- 调用超时或连接关闭时返回明确失败结果。

## 权限与审计要求

- 命令黑名单中的操作必须被拒绝。
- 显式操作受保护分支或不在允许列表中的分支必须被拒绝。
- 配置为需要确认的操作必须保存原命令，且仅允许同一用户从同一渠道在有效期内确认。
- 命令的接收及最终成功或失败必须写入审计日志。
- 已知安全边界以 [安全说明](../SECURITY.md) 为准。

## 工作站要求

- 首次认领需要本地初始化文件或预设令牌，不允许仅凭网络访问抢先建立管理员；密码至少 12 位，使用 scrypt 摘要保存。
- 会话 8 小时、访问令牌 30 天过期，原始令牌只显示一次，退出与撤销立即失效。账号角色与项目范围每次检查，原始 HTTP 身份头不能伪造身份。
- `/command` 只允许管理员调试身份，不信任请求体自报的平台用户。聊天默认拒绝未授权用户和群聊，允许使用限时一次性绑定码。
- 默认并发为 1、队列上限 100、执行前磁盘低水位 256 MiB；单轮执行、尝试、日志与输出有上限。运行配置可调整，缺失用量不得伪造精确费用。
- 项目保存仓库、分支、上下文、验证 argv、发布和执行器策略，历史版本不可覆盖，保存冲突拒绝写入。任务保存实际生效版本。
- 任务与轮次持久化后才返回受理成功；创建/续写幂等。活动轮次中断不自动重放，工作区路径、分支或会话异常必须说明。
- 成果快照相对基础提交，包含已提交、未提交与非忽略的新文件；不改变真实 index。验证记录实际命令、退出码与输出；失败阻止发布。
- 发布授权与基础提交、HEAD、tree 绑定，内容变化拒绝旧授权；开发、发布与通知失败分别展示。GitHub 远端成功但本地中断时重试须查询已有 PR。
- 归档任务只读，删除工作区必须核验归档、活动状态、唯一成果与版本；自动清理默认关闭，不能删除唯一未发布成果。
- 备份使用一致性 SQLite 快照；完整恢复按图形化停止、还原数据库/工作区/配置、核对身份与登录流程执行。诊断默认不含源码、prompt 和凭据。
- 定时功能与单条规则默认关闭，支持至少 5 分钟的固定间隔及 IANA 时区下每天 `HH:mm` 定点执行。每天定点遇到夏令时缺失时刻跳过该日，重复时刻只选择第一次；旧规则继续使用固定间隔。停机后只处理一次到期触发，再计算未来时间；同项目不重入。保存、触发、执行和发布检查角色与项目授权。
- 模板提供调查、修复、维护、自定义指令与新闻日报。默认生成待审查成果；只有项目 `policy=auto` 且规则显式选择自动交付时才自动创建 PR，自动合并另需项目 `allowScheduledMerge`。发布前读取当前授权，历史人工批准不复用。合并必须固定 PR 所属仓库、base/head 与提交，不使用管理员绕过；合并请求失败可独立重试，不重新执行采集。
- 新闻任务覆盖单次调用为实时网页搜索，记录真实完成的 JSONL 搜索事件；缺少搜索记录或来源 JSON 时任务失败。来源记录必须含标题、HTTP(S) URL、含时区的发布时间与摘要，发布时间限于触发时刻过去 24 小时，限制条数，按规范化 URL 和标题检查本次及已合入仓库的历史重复。平台生成 Markdown，交付仅允许当天 `.md` 与 `.sources.json` 两个文件；来源与 Markdown 不一致、符号链接或越界修改拒绝发布。这些校验不构成独立事实核验。
- 控制台可查看最近触发、任务和发布错误，支持禁用状态下立即试运行。试运行固定为待审查，不改变下一次执行时间；同一个 `runId` 不重复创建任务。
- 项目扩展每次检查任务范围、当前授权、允许扩展名和只读策略。动态 MCP 管理提供 CLI 和页面入口，开机连接仍由配置声明。
- 远程执行器显式配对、可撤销、主动 HTTPS 轮询，使用自己的模型与仓库凭据。租约 90 秒、心跳 20 秒；过期结果被拒绝，未知执行需人工核对后释放，不自动重派。控制端核对并导入补丁后验证和发布，远程补丁不超过 4 MiB。
- 项目可选独立只读审查，新会话不得覆盖开发 thread_id 与回复；报告不替代验证或批准，审查运行失败阻止发布，默认关闭。
- 当前版本实例锁阻止同目录双实例，较高数据库版本被拒绝；跨容器异常旧锁需要确认旧容器已停止后处理。多控制端、强租户隔离与默认多 Agent 并行不属于当前保证。

## 配置与数据

- 配置加载优先级为默认值 < `config.yaml` < `permissions.yaml` < 环境变量。
- npm 安装提供全局 `cpx` 命令，默认以 `~/.cpx` 为运行根，并允许通过 `CPX_HOME` 或 `--home` 覆盖；Docker 的显式配置目录继续兼容。
- CLI 应支持交互配置、初始化、读取、写入和校验。敏感值不得要求出现在命令参数中，配置展示必须脱敏。
- CLI 前台与后台启动应写入实例 PID；`status` 同时报告进程和 HTTP 健康状态，`stop` 只停止对应实例。失效 PID 记录应安全清理。
- `doctor` 应检查运行所需的 Node.js、Git、Codex CLI 和配置，`update` 应从 npm registry 检查新版本但不得静默安装。
- 无效配置必须阻止启动或热更新，不得静默降级成未知值。
- SQLite 初始化应是幂等的。
- 进程停止时应关闭 HTTP、MCP、文件监听、定时器和数据库连接。

## 验收基线

每个能力至少覆盖正常路径与主要失败路径：

- 命令解析：中英文、平台前缀、无效参数。
- 消息长连接：启停、消息去重、异常负载和原会话回复。
- 权限：允许、拒绝、确认、取消和过期。
- GitHub/MCP：未配置、远端错误、超时或断连。
- 生命周期：重复启动、前后台启动、PID 状态、HTTP 健康检查、优雅停止和配置热更新。
- Agent 任务：输入校验、完整仓库缓存、worktree 创建、Codex 会话恢复、终态等待、取消、可选 PR 发布和服务停止清理。
- 聊天 Coding Agent：自然语言协调会话、只读非 Git 启动、斜杠控制入口、旧命令兼容与任务内 Codex 优先级、GitHub 仓库与分支工具、共享 Agent 顺序、任务归属隔离、连续轮次、平台工具的 Token/会话边界、即时受理响应、异步协调回复、任务终态推送和 PR 链接。
- Web 控制台：静态资源、多套 Codex 配置持久化、`/model` 同源模型目录与推理强度联动、旧 provider 配置清理、配置测试、Codex CLI 登录 API 的状态/取消/清理、GitHub PAT 创建引导、Token 来源、验证后持久化、仓库与分支分页、Git/gh 安全注入，以及任务 API 错误路径。

具体执行命令见 [开发指南](../DEVELOPMENT.md#改动验证)。
