# Agent System 规格

状态：当前基线。本文只描述用户可观察行为；实现细节见 [系统架构](../../ARCHITECTURE.md)。

## 目标

系统应允许用户通过聊天平台或 HTTP 入口触发开发自动化任务，并在执行 GitHub、Skill 与 MCP 操作前应用统一权限控制和审计。

## 输入渠道

| 渠道            | 行为                                                           |
| --------------- | -------------------------------------------------------------- |
| 钉钉            | 通过 Stream 长连接接收命令或任务 prompt，并回传异步任务结果    |
| 飞书            | 通过 WebSocket 长连接接收命令或任务 prompt，并回传异步任务结果 |
| HTTP `/command` | 接收 `text`、`userId`、`userName`、`source`，用于本地调试      |
| Web 控制台 `/`  | 管理有序模型配置，创建和取消本机 Coding Agent 任务并查看日志   |
| CLI             | 提供 `version`、`init`、`start` 和 `stop` 生命周期命令         |

非文本聊天消息不在当前范围内。

## Web 开发控制台

- 控制台提供 Codex 登录与多配置页面。用户可新增、删除、保存和切换多套配置，每套包含名称、模型和推理强度，不保存 API Key 或 Base URL。
- 模型目录必须在 Codex 登录后通过 CLI 读取，与交互式 `/model` 使用同一目录；推理强度只能从所选模型声明支持的值中选择。
- 配置按页面顺序写入数据库相邻的 `console-settings.json`，当前配置用于 Web 任务；聊天任务仅在额度或鉴权失败后依次尝试其余配置。不再支持的旧 provider 配置必须在加载时忽略。
- 测试区使用当前配置发起真实 Codex 调用。测试内容最多 4000 字，回复最多 16 KiB；内容和回复不得持久化，不得返回未经解析的 CLI 事件流。
- 服务提供 Codex 官方设备码与 API Key 登录 API；设备码和账号凭据不得写入项目配置，服务停止时必须清理等待中的登录进程。
- 控制台提供独立 GitHub 页签。没有 Token 时，页面必须提供预填 Contents、Pull requests、Workflows 写权限和有限有效期的 fine-grained PAT 创建入口，并说明选择仓库、生成、复制回填的步骤；cpx 不得声称能从 GitHub PAT 页面自动取得 Token。
- 用户可直接验证 `config.yaml` 或环境变量中的 GitHub Token，也可输入新 Token；状态接口必须返回 `none`、`file` 或 `environment` 来源。新 Token 仅在验证成功后写入 `config/config.yaml`，验证失败不得修改配置，环境变量 Token 不得复制到配置文件。系统分页读取该 Token 可访问的个人、协作及组织仓库。
- GitHub 仓库列表支持筛选，并可将仓库名称带入新任务表单。任务表单也应直接列出当前 Token 明确授权的未归档项目；选定项目后分页读取现有分支，用户可选择一个分支作为任务基线，或输入合法名称新建任务分支，同时保留手动输入仓库地址和基础分支的能力。fine-grained Token 的仓库范围以 GitHub 授权范围为准。
- 仅接受 `owner/repo`、GitHub HTTPS 或 GitHub SSH 仓库地址。首次使用时必须完整克隆到 `repositories/<owner>/<repo>`，后续任务先 fetch 再从该缓存创建独立 worktree 和自动 `cpx/task-<id>` 分支；新建分支时使用用户提供的名称。创建 Pull Request 时必须以所选基础分支为 base。
- 验证成功的 Token 必须立即用于 GitHub API、HTTPS clone/push 和 `gh pr create`。Token 只能通过受控子进程环境和不含密钥的凭据 helper 传递，不得出现在 Git URL、命令参数、任务对象或日志中；SSH 地址继续使用 SSH 凭据。
- Codex 以非交互方式执行。任务可取消，状态包括排队、准备、执行、发布、完成、失败和取消。
- 控制台必须采用任务列表、单任务会话流和统一底部输入框布局；用户可随时新建任务，或在终态任务中从同一输入框追加 prompt。执行中的任务禁用输入并提供停止操作。
- 左侧任务列表不得产生横向滚动；过长任务标题最多显示两行，并在悬停时提供完整文本。用户展开“运行详情”后，任务轮询刷新不得自动折叠该区域。
- 后续轮次复用原 worktree、任务分支和 Codex `thread_id`；每轮必须保存用户 prompt、状态和 Agent 最终回复，以便在会话流中回放。运行日志应作为次级详情折叠展示，不得取代主要对话。
- Web 控制台不展示 Pull Request 开关或链接，默认只把改动保留在任务 worktree。后端受控发布流程仍可供聊天开发命令和兼容 API 使用；已有 Pull Request 存在时，发布轮次通过推送新提交更新该 PR。
- 任务、状态、轮次、Agent 回复和最多 800 条日志仅保存在内存中；服务重启后不恢复。完整仓库缓存与 worktree 保留在磁盘。
- 控制台 API 当前没有认证，不得直接暴露到公网；具体边界见 [安全说明](../SECURITY.md)。

## 命令能力

### 基础命令

- 查看版本和帮助。
- 列出已安装 Skill 和已记录 MCP 连接。
- 使用中文或英文确认、取消待执行的危险操作。

### GitHub

- 聊天命令可查看当前 Token 对应账号和最近仓库，也可按 `owner/repo` 查看现有分支。
- 在配置 Token 和默认仓库后读取文件。
- 为文件修改创建功能分支、提交和 Pull Request。
- 为新文件创建功能分支、提交和 Pull Request。
- 不直接修改默认分支。

自动修改目前只根据描述追加 Markdown 小节，不提供通用代码生成或补丁能力。

### 聊天 Coding Agent

- 钉钉、飞书和 HTTP 命令入口支持 `开发 <owner/repo>[#基础分支] [-> 新分支] <需求>`。基础分支省略时使用仓库默认分支；新分支省略时自动生成 `cpx/task-*`。
- 创建任务前必须确认当前 GitHub Token 能访问目标仓库、仓库未归档、基础分支存在，并在用户指定新分支时确认它尚不存在。
- 聊天开发任务复用 Web 控制台保存的 Codex 配置顺序，启用额度或鉴权失败时的顺序回退，不允许消息覆盖模型、推理强度或 API Key。
- 聊天开发任务默认提交改动、推送任务分支并创建以所选基础分支为 base 的 Pull Request。Agent 没有产生改动时成功结束但不创建 PR。
- 用户可通过 `继续 <任务ID> <需求>` 追加一轮。飞书和钉钉没有会话任务时，未命中命令的普通文本应使用 `github.defaultRepo` 创建任务，未配置时提示先用 `开发` 命令。建立任务后，除新建、续写、列表、状态、取消、帮助、版本和确认流程以外的所有文本，包括能匹配旧 GitHub、Skill 或 MCP 命令的文本，都应作为 prompt 继续当前来源会话最近的任务。当前轮次执行中不得并行追加。
- 消息平台任务应向 Codex 提供任务范围的 `cpx_platform` MCP 工具：可读取当前平台和任务范围，并可向创建任务的原会话发送阶段性文本。工具不得接受可更换的用户或会话目标；最终回答仍由 cpx 自动回传。
- 创建命令必须立即返回任务 ID；任务完成、失败或取消后，系统通过创建来源的平台原会话推送 Agent 最终文本回答、任务状态和 PR 链接。
- 用户可通过完整任务 ID 或唯一前缀查询、继续、取消任务，并列出最多 10 个最近任务。消息任务仅允许创建它的同一来源平台、同一用户操作；飞书和钉钉的自然语言续写优先限定原会话，即使同一用户从其他会话显式续写，平台工具与异步终态仍回到创建任务的原会话。Web 控制台创建的任务不出现在个人消息任务列表中。
- 消息任务归属与等待通知均保存在内存中，服务重启后不恢复。命令受操作黑名单约束，创建和终态应记录 `agent_delegate` 审计。

### Skill

- 从 npm、Git 或本地标识安装包的底层能力由 `SkillInstaller` 提供。
- 已安装 Skill 可按名称加载和执行，并受可配置超时限制。
- 只有 manifest 声明相应权限时，执行上下文才注入 GitHub 或 MCP 服务。
- 聊天命令支持执行和列出 Skill；CLI 尚未暴露安装、卸载命令。

### MCP

- 从配置自动连接服务，也可通过命令连接或断开。
- 支持 stdio、WebSocket 和 HTTP 传输。
- 完成 MCP 初始化握手后，以 JSON-RPC 2.0 调用方法。
- 调用超时或连接关闭时返回明确失败结果。

## 权限与审计要求

- 命令黑名单中的操作必须被拒绝。
- 显式操作受保护分支或不在允许列表中的分支必须被拒绝。
- 配置为需要确认的操作必须保存原命令，且仅允许同一用户从同一渠道在有效期内确认。
- 命令的接收及最终成功或失败必须写入审计日志。
- 已知安全边界以 [安全说明](../SECURITY.md) 为准。

## 配置与数据

- 配置加载优先级为默认值 < `config.yaml` < `permissions.yaml` < 环境变量。
- 无效配置必须阻止启动或热更新，不得静默降级成未知值。
- SQLite 初始化应是幂等的。
- 进程停止时应关闭 HTTP、MCP、文件监听、定时器和数据库连接。

## 验收基线

每个能力至少覆盖正常路径与主要失败路径：

- 命令解析：中英文、平台前缀、无效参数。
- 消息长连接：启停、消息去重、异常负载和原会话回复。
- 权限：允许、拒绝、确认、取消和过期。
- GitHub/MCP：未配置、远端错误、超时或断连。
- 生命周期：重复启动、优雅停止和配置热更新。
- Agent 任务：输入校验、完整仓库缓存、worktree 创建、Codex 会话恢复、终态等待、取消、可选 PR 发布和服务停止清理。
- 聊天 Coding Agent：命令与飞书/钉钉任务路由、旧命令文本的 Codex 优先级、GitHub 仓库与分支验证、共享 Agent 顺序、任务归属隔离、连续轮次、平台工具的 Token/会话边界、即时受理响应、异步终态推送和 PR 链接。
- Web 控制台：静态资源、多套 Codex 配置持久化、`/model` 同源模型目录与推理强度联动、旧 provider 配置清理、配置测试、Codex CLI 登录 API 的状态/取消/清理、GitHub PAT 创建引导、Token 来源、验证后持久化、仓库与分支分页、Git/gh 安全注入，以及任务 API 错误路径。

具体执行命令见 [开发指南](../DEVELOPMENT.md#改动验证)。
