# 安全说明

本文记录当前代码实际提供的安全控制和已知边界。它不是通用 Web 安全清单。

## 需要保护的资产

- 钉钉、飞书和 GitHub 凭据。
- MCP 连接参数及其可访问的外部资源。
- Skill 获得的文件系统、网络、GitHub 或 MCP 能力。
- SQLite 中的命令确认、Skill 元数据、连接状态和审计记录。
- Coding Agent 的 CLI 凭据、GitHub 工作区、任务提示与执行日志。

## 当前控制

### 消息平台长连接

钉钉 Stream 和飞书 WebSocket 均由服务主动发起出站连接，使用应用凭据鉴权，不注册入站 HTTP 回调，也不保存固定群机器人 Webhook。应用 Secret 属于敏感配置，状态 API 只返回是否已配置。

### Git 操作限制

权限管理器支持：

- 受保护分支列表，默认包含 `main`、`master` 和 `production`。
- 允许分支的 glob 列表，默认允许 `feature/*`、`dev/*` 和 `hotfix/*`。
- 禁止 Git 操作列表。
- 需要二次确认的操作列表。

确认记录保存在 SQLite 中，带过期时间，并校验确认用户与命令来源。权限 YAML 可热更新。

### 审计

系统记录命令接收、完成或失败，以及 Skill、MCP 和危险操作相关事件。审计数据保存在本地 SQLite；当前没有远程防篡改存储或内置清理策略。

### 配置校验

配置按默认值、YAML、环境变量的顺序合并，再通过 Zod 校验。敏感值不应写入版本控制；部署时优先使用环境变量或外部密钥管理系统。

## 重要边界

### HTTP 端点与身份

`/api/console/*`、`/api/workbench/*` 和 `/command` 要求管理员会话或有权限的访问令牌。静态登录资源与最小 `/health` 不携带业务数据。初始化凭据来自数据库相邻的 `bootstrap-token.txt` 或预设 `CPX_BOOTSTRAP_TOKEN`；认领后保存带随机盐的 scrypt 密码摘要，删除初始化文件。

浏览器会话为 HttpOnly、SameSite=Strict，8 小时过期，写请求校验 CSRF 和 Origin；HTTPS 登录设置 Secure Cookie。访问令牌为随机值，数据库只保存 SHA-256 摘要，30 天过期，可立即撤销。账号禁用或移除项目权限后，每次请求与任务执行检查都会使用当前账号。登录按实际 socket 地址限制失败尝试，不信任用户伪造的身份或转发地址。

HTTP 层会删除客户端伪造的内部身份头。`/command` 只允许管理员，固定使用管理员调试身份，不信任请求体自报的用户与来源。聊天身份来自 SDK 事件，需显式账号授权或一次性绑定；默认不允许群聊，账号可限定会话。普通成员只访问授权项目，审查者不能执行续写。

内部平台、项目扩展与远程执行器使用各自独立的范围令牌，不接受管理员身份头作为授权。扩展调用检查活动轮次与当前项目授权，恢复后重新签发运行时令牌。平台工具锁定原用户和会话，不能由 Agent 改目标；平台调用仍需要检查当前聊天身份有效。

请求体上限为 10 MiB；登录有限流，任务队列有容量上限。没有内置 TLS 或覆盖全部业务接口的通用限流，跨机器访问仍应经过 HTTPS 和可信网络策略。静态资源的 CSP、禁止 MIME 嗅探及禁止嵌入不能替代身份与执行隔离。

### Coding Agent 执行与交付

- 每任务独立 worktree；完整仓库缓存按 owner/repository 组织，仓库地址拒绝无有效名称的路径片段。当前版本实例锁阻止多个实例共享同一运行目录；容器异常重建的残留锁必须先确认旧容器停止，再通过文件管理器处理。
- Web、聊天、定时任务共用持久任务管理器和执行 guard。操作黑名单、归属、项目角色和受保护发布分支在服务端检查，关键工作站操作记录 SQLite 审计。审计没有远端防篡改保证。
- 生产工作站任务不向 Agent 注入 GitHub 发布凭据，覆盖 CLI 为 workspace-write、工具网络关闭与不允许扩大审批。模型 API Key 在需要时仍交给模型 CLI；Codex 自己的登录资料由 CLI 管理。历史程序化无工作站配置的适配路径仍保留原有行为。
- **这些措施不是强隔离**：Codex CLI 的限制依赖其版本和实际执行环境，宿主上已有登录文件、用户验证命令、可信 Skill/MCP 和共享服务账户仍属于信任边界。成员与仓库应可信；不能据此承诺互不信任租户隔离或绝对阻止所有外部写入。
- 发布由独立服务持有 GitHub 凭据，绑定审查快照的基础提交、HEAD 与 tree；成果版本变化拒绝使用旧批准，推送明确提交与任务分支，受保护分支被拒绝。发布目标固定为任务仓库，gh 显式指定仓库，并覆盖本地发布 hook；可影响目标或认证的仓库级 URL rewrite、pushurl、SSH 命令或 HTTP/credential 配置被拒绝。预授权自动发布仍须通过验证结果检查。
- 发布失败保留成果，重试前查找已有 PR；SQLite 与 GitHub 没有跨系统原子事务，崩溃后需要对账，外部写入不能靠“取消任务”回滚。
- 定时任务默认审查，自动创建 PR 需项目与规则双重授权；自动合并还需项目单独允许。执行及每次远端发布写入再次检查当前授权。自动合并固定仓库、PR base/head 和提交，使用 GitHub 自身的检查、审查与合并队列，不使用管理员绕过。GitHub 接受自动合并后由 GitHub 管理后续执行；本地暂停任务或撤权不会取消已经发出的请求，需在 GitHub 关闭自动合并或关闭 PR。
- 新闻模板通过 Codex 内置实时网页搜索获取资料，保持 shell 工具网络关闭且不注入 GitHub 发布凭据。来源 JSON 有大小、条数、协议、时间窗口与重复校验，拒绝符号链接和当天文件以外的交付改动；平台生成并核对 Markdown。搜索完成事件只能证明调用发生，不能证明每条新闻真实、来源可信或发布时间正确；网页内容仍可能包含提示注入，可信执行环境与人工审查边界不变。
- 任务、轮次、日志、用户输入、基础提交、项目版本、归属和通知持久化到 SQLite，属于敏感业务数据。日志对已知服务密钥脱敏且有条数上限；Agent 或工具仍可能输出未识别的秘密，diff 本身可能包含仓库中的敏感内容，因此查看与导出始终需要任务权限。
- 子进程输出上限 8 MiB，超出时失败而不静默截断补丁。验证命令记录实际退出码，失败阻止发布；这些命令仍可执行任意受信代码。
- 中断任务不会自动重跑；远程租约失效不自动重派。恢复前应检查外部副作用及旧进程已停止。进程组终止只能管理受控子进程，主动脱离进程组或向外部服务派发的工作不在回滚保证中。
- 终态和通知事件在同一个 SQLite 事务中保存。通知采用至少一次尝试投递，不能保证平台绝不重复；通知失败不触发重新开发。通知保存本轮摘要快照，避免后续轮次改变待发送内容。
- 模型连通性测试仍产生真实模型请求，测试内容不持久化，回复最多 16 KiB；不要把模型回复视为验证成功证据。

### Skill 与 MCP

Skill 安装调用 npm，使用参数数组而非 shell 字符串；管理员负责信任包来源与安装脚本。执行在受管理的独立子进程，默认移除继承环境中的 Token、Secret、密码与 API Key，通过 IPC 按 manifest 注入 GitHub/MCP 能力，超时或服务停止时终止进程组。

子进程不是文件或网络安全沙箱，任意插件仍可能自行访问宿主资源。项目扩展通过短期范围工具调用，限定显式扩展名；审查/本地策略只代理只读操作。任务内 Skill 的 GitHub RPC 限定目标仓库与任务分支，不能代理创建任意分支或 PR。MCP 配置本身可启动进程或访问外部资源，其权限取决于管理员认可的服务配置。

### 远程执行器

远程执行默认关闭。执行器需管理员配对，原始令牌只显示一次，数据库保存摘要，可撤销。工作进程主动通过 HTTPS 轮询（回环测试可使用 HTTP），不要求 NAS 终端或入站平台回调。

控制端不下发长期 GitHub、Codex 密钥；执行机需要自己的登录与读取仓库权限。任务按基础提交和种子补丁运行，补丁上限 4 MiB，结果附摘要校验，控制端核对本地成果未变后导入。摘要验证传输一致性，不证明代码安全。

领取后有 90 秒租约与 20 秒心跳，撤销、过期或已处理的结果被拒绝；未知执行需管理员确认停止后解除占用。远程执行器属于可信执行环境，不能向不可信机器发送私有代码和 prompt；配对令牌不能与管理员 API 令牌混用。

### 外部连接

- GitHub Token 应使用满足任务所需的最小权限，并限制到必要仓库。
- GitHub 页生成的是外部 PAT 创建链接，Token 必须由用户从 GitHub 手工复制回填；服务不会接收 GitHub 账号密码或 OAuth refresh token。
- 验证成功的 GitHub Token 以明文保存在 `config/config.yaml`（环境变量来源除外），应限制配置目录读取权限。HTTPS Git 子进程通过环境变量和不含 Token 的 askpass helper 鉴权，不得把 Token 拼入远端 URL 或记录到任务日志。
- stdio MCP 可以启动本地进程，配置文件本身应视为可执行权限。
- WebSocket 与 HTTP MCP 地址应指向可信服务，生产环境使用加密传输。
- 可选的 Mihomo 部署把代理配置保存在 `data/mihomo/config.yaml`；其中的订阅地址和节点凭据属于密钥材料。默认 Compose 不向宿主机映射 Mihomo 代理或控制端口，不应为方便调试把这些端口直接暴露到公网。
- `APT_MIRROR` 和 `NPM_REGISTRY` 允许镜像构建使用第三方 Debian/npm 镜像；构建者必须信任所选镜像服务并审查构建输出。这些值只作为 build args 使用，不应携带认证凭据，也不会写入最终容器环境。
- 日志与错误信息不得包含 Token、应用 Secret 或完整敏感负载。

## 生产部署最低要求

1. 为钉钉和飞书配置最小权限的应用凭据，并限制机器人可用范围。
2. 不对公网开放 `/command`、控制台页面或 `/api/console/*`；通过网络策略限制管理入口。
3. 在 TLS 终止、认证和限流网关之后运行服务。
4. 使用最小权限 GitHub Token，并限制 Skill 与 MCP 来源。
5. 限制配置、SQLite、日志、Skill 安装目录、`data/repositories` 和 `data/workspaces` 的文件权限。
6. 定期执行 `npm audit`、备份 SQLite，并审查审计记录。

## 漏洞处理

安全问题不应在公开 Issue 中附带密钥、利用代码或用户数据。项目建立私密报告渠道前，请先联系仓库维护者并仅提供最小复现信息。
