# 智能代理系统需求文档

## 产品概述

### 产品名称
Agent System（智能代理系统）

### 产品定位
一个基于 TypeScript 开发的智能代理系统，支持钉钉和飞书远程操作、插件扩展和多 Agent 协作，可发布为 npm 应用或通过 Docker 云端部署供开发者使用。

### 目标用户
- **开发者**: 需要自动化开发流程的工程师
- **团队**: 需要远程协作和任务管理的开发团队
- **企业**: 需要智能自动化解决方案的企业用户
- **个人用户**: 需要在 NAS 或云服务器上自托管服务的个人开发者

### 核心价值
- 通过钉钉或飞书实现远程控制，随时随地管理任务
- Docker 云端部署，不受本地环境限制
- 插件化架构，灵活扩展功能
- GitHub 代码远程修改，移动端也能修改代码
- 多 Agent 协作，任务分发和结果聚合
- npm 发布和 Docker 镜像，方便集成和部署
- 权限控制和安全保障，防止意外操作

#### 功能描述

#### 功能列表
| 功能 | 优先级 | 描述 |
|------|--------|------|
| 主分支保护 | P0 | 禁止直接推送 main/master 分支 |

| 操作黑名单 | P0 | 配置禁止执行的命令/操作 |

| 操作审计日志 | P1 | 记录所有危险操作日志 |
| 操作回滚 | P2 | 支持撤销最近操作（可选） |

#### 技术要求
- 默认禁止推送主分支（main/master）
- 权限配置支持热更新（无需重启）
- 所有危险操作记录详细日志
- 权限违规返回清晰错误提示

#### 权限配置示例
```yaml
# permissions.yaml
git:
  # 禁止操作的分支
  protected_branches:
    - main
    - master
    - production

  # 允许操作的分支（优先级高于禁止）
  allowed_branches:
    - feature/*
    - dev/*
    - hotfix/*

  # 禁止的操作
  forbidden_operations:
    - force_push
    - delete_branch
    - delete_repository

  # 需要二次确认的操作
  confirm_operations:
    - delete_file
    - merge_to_main
```

#### 安全检查流程
```
接收命令 → 权限检查 → 分支验证 → 操作确认 → 执行操作 → 记录日志
```

1. **接收命令**: 收到 Git 操作命令
2. **权限检查**: 检查用户是否有执行权限
3. **分支验证**: 检查目标分支是否在保护列表
4. **操作确认**: 如果是危险操作，要求用户确认
5. **执行操作**: 在安全分支上执行操作
6. **记录日志**: 记录操作详情到审计日志

#### 技术要求
- 默认禁止推送主分支（main/master）
- 权限配置支持热更新（无需重启）
- 所有危险操作记录详细日志
- 权限违规返回清晰错误提示
- TypeScript 类型定义完整
- 文档清晰易懂

## 用户流程

### 首次使用流程

#### npm 安装方式
```
安装 → 初始化 → 配置 → 启动 → 测试 → 正常使用
```

**详细步骤**:
1. 用户通过 npm 安装 agent-system
2. 用户运行 `agent-cli init` 创建配置文件
3. 用户编辑配置文件，填写钉钉/飞书 Webhook、GitHub Token 等
4. 用户运行 `agent-cli start` 启动系统
5. 用户在钉钉/飞书发送测试命令验证
6. 用户安装所需 Skill 和 MCP
7. 用户开始正常使用

#### Docker 部署方式
```
准备环境 → 拉取镜像 → 配置挂载 → 启动容器 → 测试连接 → 正常使用
```

**详细步骤**:
1. 用户准备云服务器或 NAS Docker 环境
2. 用户拉取 Docker 镜像 `docker pull agent-system:latest`
3. 用户创建配置目录和挂载卷
4. 用户通过环境变量或配置文件配置 Agent
5. 用户启动 Docker 容器
6. 用户在钉钉/飞书发送测试命令验证
7. 用户查看日志确认运行正常
8. 用户开始正常使用

**Docker 启动示例**:
```bash
docker run -d \
  --name agent-system \
  -e DINGTALK_WEBHOOK=https://oapi.dingtalk.com/robot/send?access_token=xxx \
  -e DINGTALK_SECRET=xxx \
  -e FEISHU_WEBHOOK=https://open.feishu.cn/open-apis/bot/v2/hook/xxx \
  -e GITHUB_TOKEN=ghp_xxx \
  -v $(pwd)/config:/app/config \
  -v $(pwd)/data:/app/data \
  -v $(pwd)/logs:/app/logs \
  agent-system:latest
```

### 日常使用流程

```
发送命令 → Agent 解析 → 执行任务 → 返回结果 → 用户查看
```

#### 详细步骤
1. 用户在钉钉/飞书发送命令（如 `@agent 修改 README`）
2. Agent 收到命令并解析
3. Agent 根据命令类型执行相应操作
4. Agent 将执行结果返回到钉钉/飞书
5. 用户查看结果并做下一步决策

#### 典型使用场景

**场景 1: 修改 GitHub 代码**
```
用户: @agent 修改 README.md，添加安装说明
Agent: 收到修改请求，创建分支 feature/update-readme
Agent: 已修改 README.md 文件
Agent: 已创建 PR: https://github.com/user/repo/pull/123
Agent: 请查看 PR 并合并
```

**场景 2: 执行 Skill**
```
用户: @agent 执行代码审查
Agent: 正在执行代码审查 Skill...
Agent: 发现 3 个潜在问题：
       1. src/main.ts:45 - 未使用的变量
       2. src/utils.ts:12 - 缺少错误处理
       3. src/api.ts:78 - 性能问题
Agent: 详细报告已生成，是否需要修复？
```

**场景 3: 权限保护**
```
用户: @agent 修改 main 分支的 config.yaml
Agent: ⚠️ 错误：main 分支受保护，禁止直接修改
Agent: 建议：请在功能分支修改，或使用 @agent 创建功能分支
Agent: 示例：@agent 切换到 feature/config-update 分支
```

### 管理维护流程

```
检查状态 → 安装/卸载组件 → 配置调整 → 重启系统 → 监控运行
```

#### 详细步骤
1. 用户检查 Agent 运行状态
2. 用户安装或卸载 Skill/MCP/Agent
3. 用户调整配置参数
4. 用户重启 Agent 系统
5. 用户监控运行日志和状态
