## 文档编写规范

### 命名规则
- 使用小写字母和连字符
- 文件名应清晰表达功能
- 示例: `user-authentication.md`

### 文档结构
```markdown
# 功能名称

## 背景
[功能背景和目标]

## 用户故事
作为 [角色]
我想要 [功能]
以便于 [价值]

## 功能描述
[详细功能描述]

## 验收标准
- [ ] 标准 1
- [ ] 标准 2

## 技术要求
[技术实现要求]

[关联文档链接]
```

## 优先级定义

| 优先级 | 说明 | 示例 |
|--------|------|------|
| P0 | 必须有，否则无法发布 | 核心功能 |
| P1 | 应该有，影响用户体验 | 重要功能 |
| P2 | 可以有，锦上添花 | 优化功能 |
| P3 | 未来考虑 | 备选功能 |

## 状态定义

| 状态 | 说明 |
|------|------|
| 草稿 | 初稿，待评审 |
| 评审中 | 正在评审 |
| 已批准 | 评审通过，可开发 |
| 开发中 | 正在开发 |
| 已完成 | 开发完成，已验收 |
| 已归档 | 不再维护 |
