# P0–P2 实施计划

状态：实现及本地验证完成，随本次提交推送。范围由用户在产品演进提案推送后确认：开发 P0 到 P2，完成验证后推送远程。执行负责人：本次开发会话；产品决策采用提案建议的单机优先、显式授权与默认单任务执行。

## 实施顺序

1. P0：管理员认领、登录与访问令牌；聊天授权；任务持久化、串行队列、幂等、中断恢复；diff、验证记录、独立发布与通知。
2. P1：版本化项目档案、任务深链接与身份绑定、容量和工作区管理、运行状态及一致性备份。
3. P2：模板和定时任务、扩展管理与子进程执行、项目成员权限、出站轮询远程执行器。
4. 更新事实文档与数据库说明，完成构建、测试、lint 和发布包检查，提交并推送当前分支。

## 验证要求

- 认证、越权、撤销、CSRF；不同入口一致的项目与任务权限。
- 创建后重启、运行中中断、重复请求、队列容量、通知重试。
- 已提交和未提交 diff、验证失败、成果版本变化、发布失败独立重试。
- 项目版本、定时触发去重与撤权、远程租约失效与旧结果拒绝。
- 图形化入口可使用；NAS 部署不依赖终端。

## 实际限制与外部验证

- 未进行目标极空间硬件、真实 Codex 模型账号、飞书/钉钉及 GitHub 云端发布联调，不能用模拟和本地远端结果宣称外部环境已验证。
- 角色约束是应用层权限，Skill 子进程和 CLI 沙箱不构成强租户隔离；执行环境与 GitHub 身份仍共享，只面向可信成员和仓库。
- 远程项目暂不支持控制端项目扩展；API 明确拒绝该组合。执行机需要自己的模型与仓库凭据。
- 独立审查为顺序的新会话，默认关闭；没有自动并行多 Agent 或多控制端调度。
- 定时功能使用固定间隔与显示时区，不提供任意 cron；动态 MCP 连接需要配置文件才能开机重连。
- 旧版未持久化的 prompt、日志、归属不能恢复；只列出遗留工作区供人工核对，不猜测历史。
- 数据库使用版本 1 的兼容新增表，较高版本拒绝打开。完整回滚需要匹配的数据、工作区和程序备份，不能只更换镜像。
