# 任务工作站使用与升级

本文描述当前实现的 P0–P2 功能。产品取舍背景见 [产品演进提案](PRODUCT-EVOLUTION.md)，实际接口与边界见 [系统规格](specs/agent-system.md) 和 [安全说明](SECURITY.md)。

## 认领与登录

首次启动后打开控制台，填写初始化令牌和至少 12 位管理员密码。初始化令牌默认位于数据库相邻的 `bootstrap-token.txt`，文件权限为 `0600`；极空间用户通过文件管理器打开 `data/bootstrap-token.txt`。也可在 Compose 环境变量界面预设至少 24 个字符的 `CPX_BOOTSTRAP_TOKEN`。初始化后文件被删除，环境变量不再用于登录。

后续使用管理员密码登录。密码以带随机盐的 scrypt 摘要保存；浏览器使用 HttpOnly、SameSite=Strict 的 8 小时会话，写请求校验 CSRF。HTTPS 页面登录时设置 Secure Cookie。请通过可信网络或 HTTPS 反向代理访问，不在不可信网络传送密码或访问令牌。

“项目与运行管理 → 用户与令牌”可以创建可信成员、签发 30 天访问令牌和立即撤销令牌。原始令牌只在签发时显示一次，数据库保存其 SHA-256 摘要。成员可在登录窗口使用个人令牌；浏览器只在当前标签页会话存储中保留它。退出会同时撤销当前凭据。

| 角色 | 能力 |
| --- | --- |
| 管理员 | 配置实例、管理身份、全部任务、扩展、备份与执行器 |
| 项目维护者 | 授权项目的规则、任务与发布管理 |
| 发起者 | 在授权项目发起任务，管理自己的任务；发布使用项目预授权或由审查者处理 |
| 审查者 | 读取授权项目任务、审查与发布；不能续写或修改项目规则 |

成员共享实例的执行环境与 GitHub 凭据，不构成互不信任成员之间的操作系统隔离。只有管理员可以创建未绑定项目的临时仓库任务。

## 授权聊天账号

有两种方式：

1. 管理员创建 `feishu:用户ID` 或 `dingtalk:用户ID` 账号，配置角色和可用项目。
2. 已登录用户在“身份绑定”生成一次性绑定码，在自己的飞书或钉钉中向机器人发送 `/bind <绑定码>`。绑定码 5 分钟内有效，成功后不能复用；管理员可解绑。

身份取自平台 SDK 接收的事件，不使用用户自报姓名关联账号。不同平台不会自动互认。默认仅允许私聊；需要群聊时在账号中显式开启，也可限定完整会话路由。绑定到内置管理员的身份适用于私聊，群聊建议创建独立项目成员账号。

未经授权的用户或会话会收到拒绝说明。普通成员只能查询授权项目的仓库和分支，不能通过旧 Skill、MCP 或直接文件修改命令绕过项目范围。管理员仍可使用这些兼容入口。

平台事件 ID 用于持久去重。飞书会话路由可以跨重启恢复；钉钉临时回复地址失效或重启后，需用户向原会话再发一条消息刷新路由，然后在运行管理中重试通知。

## 项目规则与新任务

在“项目”中保存仓库、基础分支、背景规则、验证命令、发布方式、单轮时限和可选执行器。每次保存产生一个新版本，并检查编辑时的版本；历史任务保留生效规则版本，后续轮次读取最新规则。

从任务表单选择项目后，以项目的仓库和基础分支为准。管理员也可以创建临时仓库任务。项目背景用于提示 Agent 理解需求，不授予文件、网络或发布权限。仓库自身的 `AGENTS.md`、README 等仍由 Agent 在任务基础提交中读取。

任务创建成功意味着任务与第一轮输入已写入 SQLite。默认一次执行一个任务，最多排队 100 个任务，开始执行前至少保留 256 MiB 磁盘空间。运行管理可以调整容量、单轮时限和日志上限；实际 token 用量或费用未知时，不展示虚构账单。

同一任务最多运行一轮。执行中收到的补充要求保存为“待处理消息”，本轮结束后由用户选择执行或撤回。服务不会把它偷偷插入已经运行的进程。

浏览器和聊天任务使用同一个管理器。任务页可复制带 `?task=<完整ID>` 的链接；链接只定位任务，访问者仍必须登录并具有任务权限。NAS 地址无法在当前网络访问时，仍可使用聊天摘要和 GitHub PR 链接。

## 重启与恢复

任务、轮次、模型尝试、日志、基础提交、工作区、归属、协调会话 ID 和通知保存在 SQLite。仓库缓存、worktree 和未提交文件保留在磁盘。

- 尚未执行的队列项在服务启动后自动恢复。
- 已开始的执行显示“已中断”，不会自动重跑。检查工作区和外部状态后，选择继续原会话，或重建 Codex 会话后继续。
- 恢复时检查工作区路径与分支。原 Codex 会话失效时，使用“重建会话后继续”；已有工作区继续保留。
- 远程执行器失联后，不自动把任务分配给另一台机器。先在执行机确认旧执行停止，在执行器管理中解除未知租约占用，再恢复任务。
- 停止任务会向受管理进程组发送终止信号，并在超时后强制终止；已发生的远端写入不会回滚。

不要让两个实例共用同一个运行目录。当前版本通过 `data/.cpx-instance.lock` 拒绝重复实例；正常关闭会清除锁，同机已退出进程的旧锁可以自动识别。容器异常退出后重建且主机标识变化时，先在极空间确认旧容器停止，再通过文件管理器删除该锁文件并启动。删除锁前不能让旧实例继续运行。

## 审查与发布

任务页的“成果与交付”提供文件统计、Git diff、验证命令与实际退出码、补丁导出、采用、归档和独立发布。

diff 相对任务创建时的基础提交，覆盖 Agent 已提交的改动、当前未提交改动和未被 Git 忽略的新文件。快照通过独立临时 Git index 生成，不更改真实暂存区。导出使用 Git binary patch；忽略文件、外部服务产物和工作区之外的内容不在补丁中。单次子进程输出上限为 8 MiB，远程补丁上限为 4 MiB，超出时明确失败。

项目验证命令实际运行后记录命令、参数、退出码、时间与输出。未配置验证时显示“没有运行平台配置的验证命令”。验证失败仍保留成果，并阻止发布。验证命令由可信项目维护者配置，本身具有执行代码的能力。

| 发布方式 | 行为 |
| --- | --- |
| 仅保留成果 | 不由发布服务推送，可审查和导出 |
| 审查后发布 | 用户获取成果版本后明确点击发布 |
| 预授权自动发布 | 在项目策略内，验证没有失败时自动推送任务分支并创建或关联 PR |

新安装默认审查后发布。检测到旧 `console-settings.json` 时，管理员首次登录必须选择升级后的默认方式，可以保留旧版自动发布行为。未确认迁移前不接受新开发任务；项目可单独配置发布策略。

审查后的发布绑定基础提交、HEAD 和工作区 tree 的版本摘要。内容变化时旧授权被拒绝；发布服务提交固定 tree，检查并发变更，再向任务固定仓库推送明确的任务分支。影响目标或认证的仓库级 Git 配置会被拒绝；服务不执行工作区自定义发布 hook。直接推送受保护分支被拒绝。发布失败单独记录，可刷新审查后只重试发布，不重跑 Agent；创建 PR 前查询已有 PR，以便在远端成功、本地中断时对账。

审查和本地模式移除 Agent 环境中的 GitHub 密钥，并覆盖为 workspace-write、工具网络关闭和不允许扩大审批的 CLI 配置。它们仍依赖 Codex CLI 的实际执行限制；共享宿主文件、已有 CLI 配置、用户验证脚本和可信扩展不构成强隔离。需要处理不可信仓库时，应使用单独的受限运行环境，不能把此模式解释为系统级绝对禁止外部写入。

## 通知、归档和清理

终态与待通知记录在同一个数据库事务中保存，通知保留对应轮次的摘要快照。投递失败不会改变开发成果状态；最多自动尝试 8 次，逐步延长间隔，管理员可手工重试。外部平台采用至少一次尝试投递，崩溃窗口可能产生重复通知；消息包含任务与轮次事件标识。

归档不删除成果。清理先核对成果版本，只有已经归档、没有唯一未交付改动且不在运行的工作区才能删除。发布版本与当前成果不一致时拒绝清理；任务记录继续保留。自动清理默认关闭，启用后按可配置保留天数检查相同条件，每次只处理一个候选工作区。

## 模板和定时维护

“模板与定时任务”提供调查、按验收修复和维护检查三个模板。定时任务使用至少 5 分钟的固定间隔，配置 IANA 时区用于查看下次执行时间；这不是本地墙上时间的 cron 排程，夏令时不会改变固定间隔。

定时功能和每条任务都必须启用才运行。停机期间不逐次补跑；恢复后只处理一个到期触发，下一次从当前时间重新计算。同项目存在活动任务时跳过本次。每次触发检查创建者和项目授权，持久化幂等键，并强制产出待审查成果，不沿用历史人工发布批准。

## Skill 和 MCP

“扩展”页可安装/卸载可信 Skill，连接/断开 MCP，并查看版本、来源和状态。动态 MCP 连接是本次服务运行的连接；需要开机连接时仍在 `config.yaml` 的 `mcp.connections` 配置。

项目通过 `skill:名称`、`mcp:名称` 显式绑定扩展，任务获得范围受限的 `extension_call` 工具。服务每次检查任务状态、当前用户和项目授权。审查与本地任务只允许 Skill 的 GitHub 读取能力和 MCP 的资源/提示读取、工具列表等只读方法；自动发布项目才可使用预授权的扩展写能力。远程任务暂不支持控制端项目扩展，配置组合会被明确拒绝。

Skill 在受管理的独立 Node.js 子进程运行，超时和停止服务会终止其进程组。manifest 只控制父进程代理注入的服务；任意包代码仍可能自行访问文件或网络，所以只能安装可信代码。安装参数通过 argv 传递，不拼接 shell。

开发机可用以下 CLI 管理运行实例；访问令牌仅通过环境变量提供，`CPX_SERVER_URL` 默认 `http://127.0.0.1:3000`，远程地址要求 HTTPS：

```bash
# 以下命令只在开发机执行，先在当前终端设置 CPX_ACCESS_TOKEN
cpx skill list
cpx skill install <包名> --source npm
cpx skill uninstall <包名>
cpx mcp list
cpx mcp connect --file <单条MCP配置.yaml>
cpx mcp disconnect <连接名称>
```

## 可选远程执行器

在运行策略启用远程执行，在“远程执行器”创建一次性显示的配对令牌，然后把执行器标识写入项目规则。执行机需要 Git、Codex、cpx，以及执行机自己的模型登录和仓库读取凭据；控制端不下发 GitHub、Codex 密钥。

以下步骤仅在开发机执行：

1. 把配对令牌放入 `CPX_WORKER_TOKEN` 环境变量；需要读取私有仓库时配置执行机自己的 `AGENT_GITHUB_TOKEN`。
2. 运行 `cpx worker --server https://<实例地址> --dir <独立执行目录>`。
3. 保持执行器进程运行。它主动轮询控制端，同一执行器一次领取一个任务。

本机回环测试可以使用 HTTP；跨机器要求 HTTPS。执行器按控制端固定的基础提交建立自己的工作区，接收已有补丁和本轮要求，返回带摘要校验的 Git 补丁与回复。控制端检查本地成果未变后导入，再在控制端运行验证与发布。

租约有效期 90 秒，执行器每 20 秒发送心跳。租约失效、任务停止或令牌撤销后拒绝旧结果；不会自动重派未知执行。一次性配对令牌丢失时撤销后创建新执行器。当前能力是单机控制端管理若干独立执行器，不是多控制端调度集群。项目可选开启独立只读审查：实现结束后使用一个新的 Codex 会话生成审查报告，保留原开发会话；它产生额外模型调用，默认关闭，不替代真实验证或人工批准。审查进程失败会阻止发布。当前协作是顺序实现与审查，没有默认或隐式多 Agent 并行执行。

## 备份、更新和恢复

“运行与备份”可创建一致性 SQLite 快照，保存在 `data/backups/<ID>.db`，可通过极空间文件管理器取走。快照包含身份和任务等敏感数据，按密钥材料保护；诊断摘要可先预览再导出，默认不含凭据、源码和完整 prompt。

完整备份通过图形界面完成：

1. 查看活动任务，等待结束或停止；在 Compose 页面停止项目。
2. 通过文件管理器备份 `config`、`data`、`logs`。核心包括数据库、`workspaces` 和配置；仓库缓存可重建。`data/codex` 与代理配置属于额外敏感材料，按需要保留。
3. 更新程序文件或镜像，保留持久化目录，然后在 Compose 重新创建并启动。
4. 登录检查任务列表、工作区关联、Codex/GitHub 状态及消息连接，按中断任务的恢复流程继续。

恢复时先停止容器，使用文件管理器还原匹配版本的配置与数据。若使用在线数据库快照替换 `agent.db`，同时移除停机后的旧 `agent.db-wal`、`agent.db-shm`，避免混用另一时点的 WAL；还原匹配时点的工作区。确认所有旧容器均已停止后处理残留实例锁，再启动检查。不要在运行中只复制或替换一个 SQLite 文件。

当前数据库版本为 1，新增表采用兼容初始化，较高版本数据库会拒绝由本版本打开。回退旧程序前恢复匹配的数据备份，不假定单独换旧镜像就能回滚所有状态。旧版本丢失的内存 prompt、日志与归属无法重建；运行管理只列出可识别遗留工作区，管理员需先备份并在开发机核对，不自动导入或猜测归属。
